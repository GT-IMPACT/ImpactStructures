# Опциональные интеграции

Интеграции входят в Impact Structures и регистрируются в `postInit`. Отсутствующий
мод не загружает свой адаптер. При несовместимом API ошибка записывается в лог;
другие адаптеры продолжают загружаться. Обязательные зависимости самих сторонних
модов при этом сохраняются.

| Мод | Версия | Поддержка |
| --- | --- | --- |
| Applied Energistics 2 GTNH | rv3-beta-1086-GTNH | Беспроводной терминал, portable cell |
| WirelessCraftingTerminal | 1.12.16 | Беспроводной крафт-терминал, усилитель дальности |
| AE2FluidCraft-Rework | 1.5.114-gtnh | Предметы через беспроводные терминалы, бесконечная дальность и энергия |
| Baubles Expanded | 2.2.25-GTNH | Все слоты `BaublesApi`, включая терминалы |
| Forestry IMPACT | 4.2.29-impact | Содержимое рюкзаков |
| Backpack | 2.2.4-1.7.x | Обычные рюкзаки всех размеров, включая надетый; эндер-рюкзак открывает доступ к эндер-сундуку |
| Extra Utilities | 1.2.12 | Golden Bag of Holding, включая зачарованные и окрашенные мешочки |
| CoFHCore | 3.1.4-329 | API энергии для WCT, отдельного источника предметов нет |

Railcraft, InventoryBogoSorter, AdventureBackpack и Hodgepodge не подключаются.
Внешний StructureCompat для этих интеграций не требуется.

## Извлечение материалов

- Сначала проверяется основной инвентарь, затем Baubles, личный слот Backpack и доступный эндер-сундук.
  Порядок и отключение источников доступны через существующий интерфейс реестров.
- Числовой префикс ключа задаёт порядок сортировки. `0990-ae2wct` и `0991-ae2fc`
  обрабатываются до `1000-ae2-wireless`. Каждый терминал принадлежит только своему
  адаптеру; неудачное извлечение не запускает другой адаптер для этого терминала.
- ME-сеть проверяет право EXTRACT, активность точки доступа, расстояние,
  измерение и view cells. Усилитель дальности не обходит проверку прав.
  Расход энергии выполняется средствами AE2. Автокрафт и жидкости не запрашиваются.
- Симуляция не изменяет предметы, NBT, энергию и файлы. При перечислении разных
  типов предметов учитывается общий доступный запас энергии терминала.
- Backpack читается через штатное файловое хранилище. Один UUID учитывается один
  раз за запрос; между запросами снимок не кешируется. Запись происходит только
  после извлечения. Неинициализированный рюкзак считается пустым и не получает UUID.
  Пока у игрока открыт интерфейс Backpack, автоматическое извлечение из файловых
  рюкзаков пропускается, чтобы не перезаписать несохранённое содержимое интерфейса.
- Содержимое вложенных рюкзаков рекурсивно не обходится. Из рюкзаков-верстаков
  используется отделение хранения, без сетки крафта и результата рецепта.

## Сборка и проверки

Зависимости интеграций объявлены как `compileOnly`, без транзитивного подключения.
`libs/forestry-4.2.29-impact.jar`, `libs/backpack-2.2.4-1.7.x.jar`
и `libs/extrautilities-1.2.12.jar` деобфусцируются
RFG для компиляции. Остальные зависимости получаются из Maven.
Extra Utilities проверяется перед загрузкой адаптера. Поддерживаются предметы
`ItemGoldenBag`, содержимое читается из формата NBT версии 1.2.12 (`items_0`–`items_53`)
и проверяется в тестах через штатный `SlotItemContainer` мода.
GTNHLib, fastutil и JetBrains annotations нужны для типов API выбранной версии AE2.
Ни эти библиотеки, ни моды интеграций не упаковываются в JAR и не становятся
транзитивными зависимостями опубликованного Impact Structures.

```sh
./gradlew build
./gradlew testCompat
```

Обычный `test` работает без модов интеграций в runtime. `testCompat` использует их
API и проверяет изолированную загрузку комбинаций, энергию и права ME-сети,
дальность, симуляцию Forestry и файловое сохранение Backpack во временном каталоге.
Оба набора тестов входят в `check` и `build`.

Для проверки в игре: запустить клиент и выделенный сервер без этих модов, затем
с AE2, AE2+WCT, AE2+AE2FluidCraft, каждым независимым модом и всем набором.
Учитывать собственные зависимости модов. Проверить survival-строительство,
view cells, недоступную ME-сеть, пустой аккумулятор, эндер-рюкзак и сохранение
обычного рюкзака после перезапуска мира.
