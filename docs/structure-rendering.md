# Анимируемые структуры

Это отдельный рендер, не связанный с голограммами, их прозрачностью или настройками проектора.
Пакет `animation` не зависит от Minecraft и OpenGL. Пакет `render` описывает геометрию и
необязательную привязку к структуре. `render.client` содержит клиентский рендер и его жизненный цикл.
Клиентские классы вызываются только из client proxy; не храните `RenderHandle` в общих TileEntity.

## Без каналов

```java
BlockModel model = BlockModel.builder()
        .block(0, 0, 0, Blocks.iron_block, 0)
        .block(1, 0, 0, Blocks.gold_block, 0)
        .build();
RenderPart part = new RenderPart(model,
        Animations.spin(30, Vector3.UP, new Vector3(1, 0.5, 0.5)));
RenderHandle handle = StructureRenderer.INSTANCE.show(clientWorld,
        new BlockPosition(x, y, z), serverStartTick, part);
```

Блоки модели не устанавливаются в мир. Несколько `RenderPart` в одном `show` имеют общие
начало координат и часы, но независимые анимации. Для отдельного движения каждого блока
можно сделать отдельную часть на блок. Координаты ячеек целые; преобразования дробные.

## Из канала структуры

```java
StructureRenderBinding binding = StructureRenderBinding.capture(
        definition, "main", "inner_ring", clientWorld,
        new BlockPosition(controllerX, controllerY, controllerZ), facing,
        new BlockPosition(offsetA, offsetB, offsetC), UnaryOperator.identity());
Vector3 axis = StructureRenderBinding.worldOffset(facing, new Vector3(0, -1, 0));
Vector3 pivot = StructureRenderBinding.worldOffset(facing, localPivotABC);
RenderPart ring = new RenderPart(binding, Animations.spin(30, axis, pivot), true);
```

Выбираются элементы, у которых `getChannels()` содержит нужное имя. Значение канала на
предмете не используется. Снимок берёт реальные блоки и metadata из мира. Пустой канал,
воздух вместо выбранного блока или незагруженная выбранная позиция прерывают захват.
Контроллер должен сначала проверить сформированность всей структуры.

`UnaryOperator.identity()` сохраняет внешний вид. Например,
`source -> new BlockAppearance(Blocks.gold_block, 0)` задаёт визуальную замену,
не меняя реальные блоки. Координаты модели — мировые смещения от контроллера; так
сохраняется ориентация текстур установленных блоков. Для осей и центров в ABC используется
`worldOffset`; ABC отсчитывается от контроллера, B направлена вниз. Центр блока — дробная точка,
не его целочисленный угол.

Последний аргумент `RenderPart` включает скрытие оригиналов. Скрытие действует после
успешной подготовки геометрии, только на клиенте; соседние секции перестраиваются, чтобы
открыть ранее закрытые грани. Мир, инвентари, коллизии и серверная проверка не изменяются.
Разрушение или замена исходного блока закрывает сцену. При необходимости контроллер
проверяет структуру и создаёт новый снимок. Один снимок предназначен для одного размещения.

## Анимации и управление

- `Animations.spin`: вращение вокруг произвольной оси и центра.
- `Animations.move`: перемещение с `LINEAR`, `SMOOTH` или своей функцией easing.
- `Animations.loop` / `pingPong`: повторение / движение туда-обратно.
- `Animations.combine`: композиция операций.
- `IAnimation`: собственная функция `(seconds, transform)` для любых сценариев.
- `RenderTransform`: перенос, масштаб, вращение; матрицы постумножаются.
- `handle.getPlayback()`: независимый `AnimationClock` с `seek`, `setSpeed`, `setPaused`.

Время анимации измеряется в секундах. Часы принимают мировые тики, включая дробную часть.
Например, `handle.getPlayback().setPaused(true, world.getTotalWorldTime())` сохраняет текущую
позицию, а `setSpeed(-1, tick)` запускает обратное движение без скачка. `setStartTick` перезапускает
отсчёт от серверной эпохи. Синхронизируйте состояние/эпоху через пакет контроллера, а не позиции
блоков каждый кадр. В примере это обычный description packet TileEntity с сохранением в NBT.

Все операции рендера и изменения handle выполняются на основном клиентском потоке.
Вызывайте `close()` при остановке, инвалидировании контроллера и выгрузке его чанка.
Повторный `close()` безопасен. Выгрузка мира также снимает скрытие, GPU-ресурсы освобождаются
на клиентском тике. При перезагрузке ресурсов геометрия пересобирается.

## Поддержка и ограничения

Геометрия создаётся штатным `RenderBlocks` в отдельном `IBlockAccess`: внутри видны блоки
своей группы, снаружи — воздух. Используются мировые текстуры, metadata и два render pass.
Геометрия кешируется в display lists; движение меняет только матрицу. Освещение и биом
берутся у исходного размещения. Раз в секунду проверяются образцы света, включая соседние
точки для ambient occlusion; пересобираются только части с изменившимся светом.
Перезагрузка ресурсов и `invalidateGeometry()` принудительно обновляют всю геометрию.
Освещение мира и физические
тени исходных блоков не перемещаются вместе с изображением.

Модели с TileEntity или только специальным рендером отклоняются до скрытия: задайте для них
явную замену обычными блоками. Произвольные ISBRH, которым нужен настоящий `World`, TileEntity
или внешние соседи, требуют отдельной адаптации. Рендер не обещает сортировку пересекающихся
прозрачных поверхностей и полноценное участие в шейдерных shadow passes.

Хуки скрытия проходят через `RenderBlocks` и базовый `Block.shouldSideBeRendered`;
Angelica 2.2.43 также вызывает этот путь. Маска скрытия публикуется неизменяемым снимком
для потоков сборки чанков. Собственные переопределения culling у модовых блоков нужно проверять
отдельно. Анимированные текстуры уведомляют Angelica о видимости.

## Example-мод: космический лифт

Модуль `example` / `ImpactStructures-Example` собирается отдельно и не включается в библиотеку.
Оригинальная конструкция из Minecraft-блоков по мотивам космического лифта Satisfactory:
оранжевые опоры, верхняя обвязка, трос, грузовая рама. Ассеты Satisfactory не используются.

```powershell
.\gradlew.bat :ImpactStructures-Example:runClient
# Для сравнения обычного Forge renderer:
.\gradlew.bat :ImpactStructures-Example:runClient -Pangelica=false
```

JVM: Gradle — JDK 25; игра и тесты — JDK 8 через настроенный toolchain.
Подробный поблочный лог в example выключен; для диагностики включите `-PstructureDebug=true`.
В новом творческом плоском мире с командами:

1. `/istruct_example` строит лифт впереди по +Z. Либо `/istruct_example x y z` задаёт центр основания.
2. Требуется загруженное пустое пространство 19 × 65 × 19 над землёй. Команда проверяет весь объём
   перед размещением и не перезаписывает постройки. Требуется уровень оператора 2.
3. Контроллер стоит над передним краем основания: `(x, y + 1, z - 8)`. До него можно дотянуться
   снаружи; команда выводит точные координаты. ПКМ запускает цикл: 4 с ожидания, 12 с подъёма
   на 44 блока, 4 с ожидания наверху, 12 с спуска. Разгон и торможение плавные.
4. Грузовая рама использует канал `carriage`; золотое вращающееся кольцо создаётся непосредственно
   через `BlockModel`, без канала и без реальных блоков.
5. Повторный ПКМ запрашивает остановку на следующей стыковке. При разрушении структуры эффект
   отключается. Движение визуальное: стоящий на исходной платформе игрок с ней не поднимается.

Проверки: `./gradlew check` охватывает основной модуль со встроенным KotlinX и example.
`./gradlew :ImpactStructures-Example:assemble` создаёт отдельный JAR в `example/build/libs`.
Для проверки в игре: запуск/остановка, разрушение рамы/опор, повторное восстановление,
выгрузка чанков, выход/вход в мир во время движения, второй игрок, F3+T, запуск с Angelica и без неё.

## Example-мод: сфера Дайсона

`/istruct_dyson` строит три концентрических сферических каркаса диаметром **96, 72 и 48 блоков**.
Внешний занимает 6 × 6 чанков по размеру; фактическое число затронутых чанков зависит от размещения.
Каждый каркас проходит через оба полюса: 12 меридианов и 5 широтных колец, без заполнения панелей.
Используется только цветная обожжённая глина: внешняя оранжевая, средняя жёлтая, внутренняя бирюзовая.

- `/istruct_dyson [x y z]` — координаты **контроллера**. Без аргументов он ставится на три блока
  впереди игрока по +Z, на высоте ног; сфера находится дальше по +Z. Контроллер выглядит как чёрная глина.
- Центр сфер относительно контроллера: `(0, 49, 50)`. Внешний каркас занимает
  `X: -48…47`, `Y: 1…96`, `Z: 2…97`. Контроллер доступен снаружи у земли.
- Команда требует уровень оператора 2 и заранее проверяет весь загруженный пустой объём
  **98 × 97 × 99** с запасом под вращение углов блоков: `X: -49…48`, `Y: 0…96`, `Z: 0…98`.
  Постройки не перезаписываются. Используйте плоский мир и дальность прорисовки хотя бы 8 чанков.
- ПКМ запускает вращение вокруг общей вертикальной оси. **При взгляде сверху** внешний слой идёт
  по часовой стрелке со скоростью 3°/с, средний — против со скоростью 5°/с, внутренний — по часовой 7°/с.
  Повторный ПКМ выключает рендер и возвращает изображение исходных блоков.
- Слои используют каналы `dyson_outer`, `dyson_middle`, `dyson_inner` и общий серверный отсчёт времени.
  Разрушение каркаса останавливает анимацию. При выгрузке исходных чанков рендер закрывается;
  после их загрузки целая конструкция продолжает вращение с сохранённой эпохой.

Движение только визуальное: коллизии остаются у исходных блоков каркаса.
Геометрия, отсутствие заполненных панелей и направления вращения проверяются в `DysonGeometryTest`.
